대표 프로젝트 두 개에서 문제, 본인 행동, 확인 가능한 결과만 남겼습니다.

CASE 01

받는 쪽에서 확인하지 않으면 드러나지 않는 결함

상황

시세 배포는 보내는 쪽 로그만 보면 정상으로 보입니다. 구독자가 실제로 받은 데이터를 따로 확인하지 않으면 결번과 방향 오류가 그대로 남습니다.

행동

참조 구독 클라이언트를 따로 만들어 받은 데이터의 시퀀스 연속성을 상시 측정했습니다. 게이트웨이가 종목을 걸러 보내면서 전역 시퀀스를 그대로 흘리고 있던 것을 찾아 구독자별로 다시 매겼습니다. 체결 방향은 문서 값을 그대로 쓰지 않고 300건을 호가와 대조해 확인했습니다.

확인

구독자 기준 데이터 무결성이 48.5%에서 100.0000%로 바뀌었습니다. 문서가 매도로 안내한 코드는 대조한 표본에 나타나지 않았고, 매핑되지 않은 코드는 세어서 노출하도록 두었습니다. 구현에 AI를 활용한 개인 공개 프로젝트이며 측정과 판단은 본인이 했습니다.

CASE 02

같은 기업과 같은 기간을 다시 찾을 수 있는 공시 데이터

상황

재무 데이터는 건수가 많아도 회사 식별자, 보고 기준일, 출처가 뒤섞이면 같은 값을 다시 확인하기 어렵습니다.

행동

SEC EDGAR와 OpenDART에서 가져온 데이터를 회사와 기간 단위로 정리하고 재무제표 항목과 출처를 분리했습니다. 결측, 중복, 변환 결과를 별도로 확인해 수집 실패와 가공 오류가 섞이지 않도록 했습니다.

확인

공개 README 기준 6,887개 기업, 487,293건의 기록이 남아 있습니다. SEC EDGAR와 OpenDART 공개 데이터를 다룬 개인 프로젝트입니다.

이 문서에서 확인할 수 있는 것

  • 보내는 쪽이 아니라 받는 쪽에서 확인해야 드러나는 결함을 찾는 방법
  • 세션 단절과 느린 소비자를 전제로 배포 경로를 설계하고 복구를 실제로 돌려본 경험
  • 문서 값을 그대로 믿지 않고 실제 데이터와 대조해 확인하는 습관
